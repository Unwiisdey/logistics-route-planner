# 测试说明与后续计划

v1.0.0 的核心使用 CTest 注册 96 项测试，正式 UI 加入后为 98 项，双车与省时兜底加入后为 112 项，中转站/新版路网加入后为 121 项；另有 23 项 Python 回放测试。C++ 检查通过显式异常和退出码实现，Release 下也保留。核心历史 Debug / Release 已通过；当前分钟处罚规则在 Release 下验证，覆盖向上取整、步长一致性及拥堵后实际迟到。历史环境与性能数据见 [测试报告](../docs/test-report.md)。

- `graph_tests.cpp`：8 项测试，覆盖节点增删、入边/出边清理、边增删及方向、重复项和非法数值、邻接表确定性输出、三种矩阵权重、零权重与无边区分、路况数据更新、空图及复制独立性。
- `config_tests.cpp`：7 项测试，覆盖合法输入与默认值、语法与重复键、类型和缺失字段、节点/道路非法内容、加载失败不覆盖原图、文件错误与规模校验、示例数量和从每个节点出发的可达性。部分测试包含多个坏数据案例。
- `planning_tests.cpp`：12 项测试，覆盖两种 Dijkstra 权重、关闭道路、无路/同点、零权环、快照、溢出绕路、贪心行程、三项总量、子集/空任务/不同起点、途经配送点、载重和返仓失败、CSV 转义及过期计划拒绝、完整演示网络。
- Dijkstra 在 20 张固定种子的 7 节点有向图上，与独立 Floyd–Warshall 的距离/成本/耗时、全部源终点组合交叉验证，共 2940 组，包含零权和关闭边；逐组核对提前停止的点到点查询与单源结果。
- `simulation_tests.cpp`：11 项测试，覆盖时钟/跨天/非法值、车辆容量、边上位置和插值、早到等待、截止时刻开始卸货、分钟处罚（小数向上取整、可配费率、一次记账、单单/累计溢出保护）、载重扣减、0.1/0.5/1/5/100 分钟步长一致、零耗时和空任务、重复通行不重复配送、过期/关闭路线拒绝、快照独立性及两种策略的 25 点仿真。
- `order_tests.cpp`：15 项测试，覆盖窗口和小数截止边界、独立订单、严格初始规划/同点多单、紧急优先、先卸货后取货、保护原截止时间、在途/等待/卸货衔接、连续待生效插单、拒绝不改变任务/车辆、返仓后接单、旧模式升级、步长一致、JSON 校验和路线版本导出。
- `traffic_tests.cpp`：11 项测试，覆盖阈值及零基准、采样比例/恢复/随机复现、非法批次不改变图、只修复受影响区间、当前路段锁定、无关变化零搜索、低于阈值和恢复时刷新 ETA、等待/卸货衔接、预测及实际迟到分钟计罚、连续插单与路况交错、0.25/10 分钟步长一致、闲置路况及重新接单、旧模式升级和导出。
- 应用：20 项测试，含完整路况订单场景，以及非法路况间隔、种子、缺少仿真模式时拒绝路况参数。
- `test_plot_network.py`：6 项 Python 标准库测试，检查 CSV 数据读取、损坏路线、关闭道路、总量不符、缺失字段和非有限坐标；无需安装 matplotlib。
- `test_plot_simulation.py`：8 项测试，检查车辆坐标、当前道路、时间倒退、伪完成、等待状态、非有限值，以及防止将动态版本错当固定路线；无需安装 matplotlib。
- `test_plot_traffic.py`：9 项测试，覆盖同刻路况版本、尚待生效路线与当前边区别、倒退回放、损坏路况链、引用未来路况、缺少路线版本、错误坐标/衔接点，以及跨版本已走道路；无需 matplotlib。
- `fleet_tests.cpp`：11 项，覆盖距离/成本超时后的省时兜底、保留可行原策略、保护旧窗口/载重、实际共享路网和时钟、不同仓库返仓、初始容量分单、固定归属、双车紧急试算择优、无副作用拒绝、统一路况、当前道路锁定、零耗时同时完成、返仓后接单、步长/缓存开关一致性和逐车 CSV；另加 3 项 CLI 检查。
- `cache_tests.cpp`：6 项，覆盖指标/方向隔离、修改副本安全、图外降耗时、拓扑/状态变化、图身份及拷贝赋值、不可达、LRU、容量 0、非法值和无变化操作。
- `integration_tests.cpp`：3 项，对两种策略、多个种子、不同步长，比较开/关缓存的完整配送结果和路径版本，检查取货、载荷及接单拒绝。
- CLI 新增缓存禁用与非法容量 2 项；`performance_tests.cpp` 新增缓存性能冒烟 1 项。性能测试校验路径及实际搜索次数，不使用易波动的耗时阈值。

项目根目录构建完成后：

```sh
cd build
ctest -C Debug --output-on-failure
ctest -C Debug -R graph --output-on-failure
cd ..
```

第二条测试命令可选，只运行图模块。`config` 测试工作目录由 CMake 指定为源目录，应用测试读取构建目录的配置副本。

规划与导出测试运行于构建目录，临时 CSV 只写入构建目录的 `test_artifacts/`。Python 数据检查在项目根目录运行：

```sh
python -m unittest discover -s tests -p "test_plot*.py" -v
```

另已实际执行两种完整演示行程、车辆仿真与绘图脚本，检查生成图片和 GIF 帧，结果见 `docs/examples/` 与 `docs/examples/stage4/`。图形展示的人工检查不能代替算法数值测试；交互窗口的人工点击未作为自动化测试。

最终阶段已经增加 30/300/1000 节点性能对照和完整动态事件集成验证。以下属于范围之外的未来验证，不代表本版业务已实现：

| 阶段 | 验证重点 |
| --- | --- |
| 后续优化 | 真实大规模路网、长期事件存储、并发或更精细的缓存失效策略 |
| 新业务 | 封路、跨车转单、真实在线数据与大规模车队 |

算法测试应验证已知正确结果和业务约束。启发式访问顺序测试不能仅因得到一条路线就声称已证明全局最优。

- pickup_tests.cpp：7 项，覆盖新旧来源字段与冲突拒绝、真实到站装货/卸货、返原仓、非法来源与超载/窗口保护、过路不装货、双车一次领取、拥堵与步长一致性、82 边路网及 D12↔D18。另有 2 项单车/双车 CLI 和 UI 桥接内的实际中转取货测试。
- 浏览器：ui/verify_live.cjs 为通用交互，ui/verify_hubs.cjs 检查中转站下拉、任务站点、待取数量、实际完成返仓并生成当前地图/页面截图；需要先启动 8765 服务。
