# 双车 UI 设计与实现

已根据用户批准的独立 Demo 部署为正式默认界面，根目录 Start-UI.cmd 或 python scripts/start_ui.py 启动。正式入口为 8765。本页记录实际界面，不再是待实现方案。

![正式双车界面](maps/ui-hub.png)

## 页面结构

同一张地图同时展示两车，蓝色 V01、橙色 V02 配合标签区分；共享时钟控制两车同步推进。右侧为各车卡片，下面是手动订单、订单归属表、日志和前后路线对比。移动端按区块纵向排列，地图横向滑动。

每车分别显示后续道路路径、当前任务、取送任务路径、载重、状态及 ETA。返仓后保持空闲；已完成订单仍保留车辆归属。地图当前道路预计耗时与车辆入边锁定耗时分别展示。

## 交互

- 一个开始/暂停和单步控制共享时钟，不提供令时钟分叉的单车运行按钮。
- 手动订单默认由系统分配；可从仓库或中转站取货。只向选定车辆接单，拒绝时给出两车原因。
- 选中车辆可聚焦其路线，始终保留另一辆；道路可选中并模拟拥堵，受影响区间由核心重规划。
- 任务顺序直接来自核心 remaining_actions，包含当前锁定服务和待生效路线。按订单 ID 区分同点多单，完成后移除。
- 各车独立统计，顶部汇总；中转站待取数量按共享车队订单计算。刷新保留最近插入前后对比。

## 实现边界

ui/fleet.html、ui/fleet.css、ui/live.js 为当前页面源；ui/build_live.py 生成 dist，并保留历史 replay.html。ui/bridge.cpp 持有真实 FleetSimulation，UI 协议版本为 2。浏览器只输入和展示，路线、分配、时间与处罚均来自 C++。

不提供强制换车、跨车转单、联网地图或库存补货。CLI 单车模式仍可使用，但正式网页默认两车。详细使用见 [UI 手册](ui-guide.md)，验证见 [集成报告](reports/fleet-ui-integration.md)。
