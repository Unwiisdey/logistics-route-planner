## 性能方法与结果

Release 构建；每项在 5 个独立进程中重复，取毫秒中位数。网络是确定性的稀疏有向图，每节点 4 条边。图生成与独立参考路径准备不计时；查询、缓存首轮填充、路径复制与结果核对计时。相同图/请求分别容量 0 和 256；不是拿 Debug 与 Release 相比。

| 工作负载 | 节点 / 边 | 查询数 | 无缓存搜索 → 缓存搜索 | 命中 | 无缓存中位数 ms | 缓存中位数 ms |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 重复最短路 | 30 / 120 | 450 | 450 → 30 | 420 | 3.238 | 0.357 |
| 重复最短路 | 300 / 1200 | 480 | 480 → 32 | 448 | 34.333 | 2.527 |
| 重复最短路 | 1000 / 4000 | 480 | 480 → 32 | 448 | 179.772 | 12.355 |
| 12 单初始候选规划 | 300 / 1200 | 729 | 729 → 157 | 572 | 25.112 | 7.791 |

1000 节点重复查询约 14.55 倍，12 单候选规划约 3.22 倍；仅适用于上述复用工作负载。全部路径及三权重校验和与未缓存版本一致。频繁路况会使缓存失效，低复用或持续淘汰场景不保证更快；未以这些数字宣称任意图、整套仿真或全局调度均同幅提速。完整仿真的日志/快照开销不包含在本表中。

复现：

```powershell
cmake --build build --config Release
python scripts/benchmark.py --binary build/tests/Release/performance_tests.exe --runs 5 --output exports/benchmark
```

单配置生成器使用 `build/tests/performance_tests`。增加 runs 可减少噪声，不应把不同机器时间当作功能测试失败。

演示快照、摘要与动画见 [展示材料](demo/README.md)。UI 是回放，未把真实在线交通或人工点击窗口记作自动化通过。跨平台随机序列可能不同；集成测试在各工具链内比较有/无缓存，已保存 CSV 可独立回放。
