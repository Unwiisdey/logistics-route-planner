# 省时兜底与双车调度

本次用户明确追加的功能；正式网页已采用批准的独立双车 Demo 布局，与 CLI / C++ API 共用同一 FleetSimulation 核心。

## 路线决策

订单模式（--scenario / --hard-windows / --vehicles 2）先按选定的距离或成本策略规划。若固定取送顺序因为时间窗口失败，尝试对该顺序的各段用耗时最短 Dijkstra 重算，再检查所有订单的时间窗口、取货先后、载重与返仓。普通候选已经可行则保留，避免不必要的绕路。

例如从 W 到 A：直接走 1 km、20 分钟；绕行 6 km、10 分钟。15 分钟内必须送达时，使用绕行；30 分钟内送达时，距离策略仍走直接道路。若绕行也赶不上，拒绝新订单。只尝试同一动作序列的最快路径，不搜索所有可能的订单排列，也不承诺总距离或成本全局最优。最早开始卸货遵守窗口起点；截止时刻包含在窗口内。

核心在 src/planning/DynamicOrder.cpp 的 evaluate_with_metric / evaluate；结果 OrderRoute::time_fallback 表示这次候选是否采用兜底。它同时覆盖严格初始规划与动态插单；旧静态 Planner 的最近邻路线和兼容仿真行为保持原样。拥堵仍对受影响取送区间按耗时修复，不全局重排任务。

## 双车数据结构

| 数据 | 用途 |
| --- | --- |
| 一份 Graph（shared_ptr） | 两车实际引用同一邻接表与当前道路权重，不复制两套运行路网 |
| 一份 SimClock（shared_ptr） | 一个时钟统一推进；两车不会各自使时间增加一次 |
| vector<FleetVehicleSpec> | 车辆 ID、出发仓库、载重上限 |
| vector<unique_ptr<Simulation>> | 各车独立的 Vehicle、任务队列、事件、载荷、缓存和路线版本 |
| map<OrderId,string> ownership | 已接受订单到车辆的固定归属；完成后仍保留，防止重复接单 |
| vector<FleetAssignment> | 每次初始分配/动态请求的时间、结果、原因和候选任务路径 |

FleetSimulation 持有共享对象和各车状态，只向外返回只读引用。普通单车 Simulation 构造仍创建自己的 Graph / SimClock。Simulation 禁止复制、允许移动，避免活动状态被误复制。

## 分单与紧急插单

初始订单按紧急优先、截止时间、订单 ID 排序。对每辆车的已有初始订单加上新订单试算，保持总初始载荷不超过该车上限；初始货物必须位于该车出发仓库。可行方案中，普通单比较新增距离/成本，其次返仓时刻，最后车辆 ID；紧急单先比较本单开始卸货时刻，其次新增距离/成本和车辆 ID。无车可接时明确记录拒绝，继续其他订单；单笔货物不拆成两份。

执行途中也对两车分别调用只读 preview_order。试算以当前道路终点/正在卸货完成后的状态为衔接点，包括取货和全部旧订单约束；落选车辆没有拒单事件或新任务。选定后仅该车正式 insert_order。已接订单永不在车辆之间迁移，因此没有在途货物交接问题。该规则是简单启发式，不保证全局最优分配，也不自动回溯之前已确定的归属。

## 共享时钟与路况

统一事件循环取“下一个车辆阶段结束、下一次路况、当前推进目标”中最早的时间。时钟只推进一次，再更新两车的在途剩余时间。若同时遇到路况和到达，先更新未来道路，再完成各车阶段并决定下一次出发。当前道路耗时依入边时锁定，不中途把车移到别处。零耗时行驶和卸货在当前时间内连续处理，直到出现非零耗时阶段或返仓。

路况由一个 TrafficSimulator 每 30 秒采样一次。整批校验后在候选图预检两车的受影响区间，成功后发布到同一个 Graph 并提交各车预测和日志；未受影响路径保留。候选图是为批次校验所作的临时副本，不是另一辆车的独立运行路网。缓存按候选图版本查询，共享图发布该版本后可复用。

一车提前返仓后仍留在共同时间线上，可等待未来订单；全部完成后 advance 也允许推进时间。运行中实际迟到仍按 ceil(迟到分钟) × 每分钟分值计罚，默认 1，各车与总计分开汇总。

## 使用与查看结果

```powershell
.\build\Release\logistics_app.exe --plan distance --simulate --vehicles 2 --scenario config/orders.json --capacity 40 --traffic --export exports/fleet
```

默认两车为 V01 / V02，同仓库、各 40 kg；容量不是两车合计。C++ API 可分别指定仓库和容量。CLI 的 --vehicle-id 修改第一辆 ID，第二辆使用 ID_2；ID 只允许字母、数字、下划线和连字符。

本机示例：初始 O01/O02 分配到 V01，O03 分配到 V02；482 分钟发布的 URGENT01 分配到 V02；OVERLOAD01、IMPOSSIBLE01 明确拒绝。带 seed=42 路况共完成 4 单，具体时刻可能随平台标准库随机实现不同。

根目录 traffic_options.csv 保存共享随机路况的间隔、比例、倍率与种子；各车子目录的 random_enabled=0 表示车辆自身不另开随机源，路况由车队广播。completed_at() 和日志保留每车实际返仓时刻，空闲后的 snapshot.time 继续随共享时钟推进。

assignments.csv 记录分配时间、订单 ID、车辆 ID、是否接受、原因和当次候选路径；V01/ 与 V02/ 保存各车原有的 CSV。日志包含逐车完成、超时、处罚和 Fleet complete 总计。各车子目录可以分别用现有 Python 脚本回放；尚未实现两车叠加图。

## 范围

不拆单、不跨车转单、不全局求解多车最优路线、不接入真实交通。两车界面已正式部署，[界面设计与实现](fleet-ui-design.md) 提供说明与截图。v1.0.0 与保存的历史演示仍是当时的单车版本。
